## 변경 내역

### 1. 미사용 PG(토스/네이버페이) 라우터 일괄 게이트 (`f76f549`)
- 라우트별 개별 게이트의 누락(토스 `/confirm`·`/cancel`, 네이버 주문형 무인증 GET 2개) 해소 —
  3개 라우터 최상단 `router.use` 게이트로 env 미설정 시 전체 503
- **구현 중 발견한 함정**: `/payments/kakaopay`가 `/payments`(토스) 뒤에 마운트되어 있어
  라우터 게이트가 카카오페이까지 차단할 뻔함 → 구체 경로 우선으로 마운트 재정렬.
  스모크 테스트로 토스/네이버 503 + 카카오 정상 200 확인
- 참고: 프로덕션 env에 TOSS_SECRET_KEY 등이 남아 있으면 게이트가 열림 — env 제거 권장

### 2. 장바구니 IDOR 수정 (`5341108`)
- `updateCartItem`/`deleteCartItem` WHERE에 userId 소유권 필터 추가.
  타인의 cartItem UUID로 수정·삭제 가능하던 문제 해소, 미소유 접근은 404

### 3. Graceful shutdown + 프로세스 레벨 에러 핸들러 (`00393ad`)
- 시그널 핸들러를 db.ts → index.ts 이관: `httpServer.close`(진행 요청 drain) →
  `closePool` → exit 순서 + 10초 타임아웃. 기존에는 풀부터 끊고 즉시 exit라
  배포 시 진행 중 요청(결제 콜백 포함) 유실 위험
- `unhandledRejection`/`uncaughtException`: 구조화 로깅 + 텔레그램 알림,
  uncaughtException은 안전 종료 후 오케스트레이터 재기동 유도

### 4. 카카오페이 승인 경쟁 조건 차단 + tid 세션 백업 (`e761776`)
- **A-2**: `updateOrderPayment`에 `expectedStatuses` 원자적 가드(WHERE status = ANY) —
  동시 중복 콜백의 이중 확정·이중 알림·이중 장바구니 비우기 방지.
  카카오 approve가 중복 호출 에러를 반환한 경우에도 1.5초 후 주문 상태를 재확인해
  이미 확정이면 success 안내 (성공 결제가 실패 화면으로 보이는 것 방지)
- **A-3 (하이브리드, DB 무변경)**: tid를 인메모리 Map + `req.session.kakaopayTids`
  (PG 세션 스토어)에 이중 저장, 콜백은 Map 우선·세션 폴백 —
  **배포/재시작 순간 결제 진행 사용자의 승인 실패를 구제** (이번 배포부터 유효).
  컬럼 방식 대신 세션 백업을 택한 근거: 콜백은 의도적으로 세션 비의존 설계(쿠키 유실
  환경 대응)라, Map 우선+세션 폴백이면 어떤 시나리오도 현행보다 나빠지지 않음.
  tid hit 소스(memory/session)·both-miss 로그로 컬럼 필요성을 데이터로 관측 가능
